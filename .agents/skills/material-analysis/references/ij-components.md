# IJ 页面搭建规范

这是用户为材料分析成果指定的页面设计体系。适用于新生成的研究网站、门户页面、方案界面、交互原型，以及材料中展示的自制产品界面图；不限于 IDE 文件树。

## 组件库与读取方式

- 组件库：[Int UI Kit Community](https://www.figma.com/design/3q89XhaMGImDOPJwvfEpd7/Int-UI-Kit--Community-?node-id=733-46971)。
- Figma file key：`3q89XhaMGImDOPJwvfEpd7`。
- 用户提供的入口节点：`733:46971`。入口不代表所有页面组件；按当前文件结构查找任务所需的组件及样式。
- 历史项目曾用 Main Window 节点 `7070:138481` 搭建 IDE，仅供定位参考；不要将完整 IDE 外壳强加给普通研究网页。

实施时遵循当前可用的 Figma 技能与工具要求。将 Figma 设计实现为代码时，先读取 Figma design-to-code 技能；在 Figma 内新建或编辑页面时，按对应设计生成与编辑技能处理。此引用不要求每次纯文本分析都访问 Figma。

先检查仓库中是否有已实现且可追溯到该组件库的组件、token 和图标；复用经过核对的实现。需要新组件、缺少对应状态或来源不明时，再从 Figma 读取相关节点与资源，不凭记忆补出规范数值。

## 从内容到组件

先安排研究内容与阅读路径，再选择适配组件：导航、标签页、搜索输入、筛选控件、按钮、列表、表格、信息提示、弹层与工具栏等。只使用库中实际存在且与任务相符的组件；这里列举的是查找方向，不是对该库库存的承诺。

确认所选组件的结构、尺寸、内边距、字体、颜色、圆角、描边、图标与变体。交互页面还要实现实际需要的悬停、焦点、选中、禁用、错误或展开状态；不把一种状态的静态截图冒充完整组件。

- **在 Figma 中搭建**：有可用组件时优先使用真实实例及其属性、变体和变量，不无故拆散实例。
- **实现网页或原型**：Figma 本身不是可直接安装的前端组件包。复用仓库内已核对的组件，或将读取到的结构与样式实现为可复用代码组件，明确这是「基于 Int UI Kit 的代码实现」。
- **生成材料中的界面图**：先搭建页面，再从最终实现或 Figma 画面导出，不用图像生成或手绘替代要求精确复用的 UI 组件。

用统一的 token / 组件层管理重复样式，避免每页各写一套近似值。默认不混入另一套设计系统的按钮、字体或图标；用户指定新的体系时按其要求调整。

用户给定的研究变量可覆盖对应组件参数，例如字号或间距。将这些覆盖明确记录为「方案参数」，避免把本项目的 20 / 20 / 16、4px 等数值宣称为 IJ 官方规范，也不要推广到其他材料。

## 缺少组件或无法访问时

库中没有合适模式时，用已确认的 IJ 基础组件与 token 组合，并记录为扩展组件；扩展应服务具体内容和交互，不为了装饰新增模式。不能将扩展组件标注成库内原组件。

若 Figma 不可访问，优先使用已有且有来源记录的本地实现。既无法读取源组件、也没有可靠本地来源时，可以继续材料分析和内容结构设计，但不能将凭空仿制的页面称为符合 IJ 组件要求的最终成果。说明具体缺口；仅在确实影响完成页面时请求用户提供可访问的组件文件或导出资源。

## 记录来源并检查效果

在交付目录现有的来源说明或资源 manifest 中记录：本地组件/资源、Figma 文件与节点、变体或主题、复用方式，以及有意偏离源组件的参数。记录实际读取到的信息，不编造节点编号。来源说明在文档中简洁可查，不把技术映射表塞进面向读者的每个页面。

保留组件和图标原作者归属，并核对实际可见的使用条款；公开分享的文件不自动等同于任意用途许可。下载工具返回的资源时使用允许的方式，发布产物不依赖临时 Figma URL。

验证选用组件的视觉和实际布局：图形与容器尺寸分开核对，字体回退明确说明；检查主题一致性、长文本、中文、窄窗口、关键状态和真实交互。只在测试通过的范围内说明符合程度。

原始产品截图、引用图表与文档图像属于证据，不做 IJ 风格改造。若为说明差异另绘统一样式的比较示意，明确标注「结构示意 / 基于 IJ 重建」，同时保留原始来源，不把示意当成竞品原貌或测量依据。
