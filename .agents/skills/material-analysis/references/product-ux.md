# 产品与界面专项分析

仅在材料涉及产品交互、视觉规范或界面测量时读取。下文的文件树计算只适用于树形结构，不作为其他组件的默认分析框架。

## 建立可信的比较口径

区分并在材料中可见地标注：

1. 官方规范或源码：注明产品、版本或提交、平台和出处。
2. 实际界面测量：注明版本、系统、主题、UI 缩放、截图分辨率及测量方法。
3. 截图估算：给出量级或范围，说明图像缩放与样本限制。
4. 设计建议：解释推导和待验证条件，不描述成已证实的最佳值。

对最新版本、官方数值和具体来源链接进行核实。浏览器渲染得到的数值只能证明本次原型的实现，不能反过来充当竞品实测。历史 Fleet / Xcode 样本注明历史版本；VS Code 上游实现可以作为 Cursor / TRAE 的参考，但不能替代这两款产品的测量。

比较前统一测量对象：

- 箭头可见图形尺寸与箭头布局槽宽度。
- 文件图标可见图形尺寸与图标布局容器尺寸。
- 箭头槽到图标容器的间距、图标容器到名称的间距。
- 文件名字号、行高、每级缩进、根级左边距、侧栏有效宽度。

CSS px、原生 pt 和截图像素不能未经换算就作为同一实测单位。对无法确认的数据保留空缺或标注估算，不补造精确数值。

## 推导方案

将缩进、图文间距和命中区域分别处理：缩进表达层级，图文间距绑定同一条目，命中区域服务点击操作。图标容器尺寸不会自动决定最佳缩进。

采用清晰的几何定义：根节点深度 `d = 0`，左边距 `L`，每级缩进 `I`，箭头槽 `A`，槽间距 `G1`，图标容器 `F`，图文间距 `G2`。

```text
名称起点 X = L + d × I + A + G1 + F + G2
名称可用宽度 W = 侧栏内容宽度 − X − 右侧占用
```

右侧占用包括内边距、实际占位的滚动条、徽标或操作按钮，避免重复扣除已排除在内容宽度之外的区域。明确「第几层」与 `d` 的对应关系。无展开箭头的文件行也保留相同槽位，使同级文件与目录名称对齐。

推荐一个标准方案，必要时给出紧凑备选及切换条件。用相同目录和相同侧栏宽度比较，覆盖长文件名、深层目录、中文及英文名称；不要用内容不同的树得出密度优势。

## 从界面现象到体验判断

先说明用户、任务和使用条件，再分析信息层级、操作路径、状态反馈、一致性及可访问性。截图能支持可见布局观察，不能独立证明操作步数、加载性能或用户满意度。只有走通流程或有相应证据时，才下交互或效率结论。

提出视觉方案时区分布局检查与用户验证。浏览器计算样式可验证本次原型的容器、字号、间距和行高；不能用它证明竞品实测值或用户效率。比较实验可观察定位时间、误点、层级判断与截断情况，未开展的实验标注为计划。

## 原型与组件来源

用户要求效果展示时，再构建合适的原型。新生成的页面统一遵循 [IJ 页面搭建规范](ij-components.md)，采用指定 Int UI Kit 的组件、样式与图标。使用 Figma 设计时按当前可用技能读取相关节点和资源；不可访问时说明依据，不宣称精确复用。模拟代码、日志或业务结果注明演示。

保持参数、预览、标注、导出、文档和截图一致。保留组件作者与资源来源，不在发布页面依赖临时下载地址。
