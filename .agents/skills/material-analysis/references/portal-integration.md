# 将研究材料合入既有门户

## 先确定接入方式

阅读目标仓库的适用说明、目录结构、分类数据和卡片渲染方式。若目标已包含用户参考启动页，新增研究条目即可，不整站覆盖。确认目标分支、当前变更和现有部署路径。

优先沿用既有数据模型，把完整研究放入独立目录；保留相对路径，使材料可以从仓库子路径访问。避免仅链接到另一个个人网站，从而未真正合入文件。

DevEco 本次结构示例（其他仓库以实际结构为准）：

```text
index.html
site/catalog.js       分类与条目
site/launcher.js      卡片、搜索与分类交互
site/launcher.css     启动页样式
analysis/<slug>/      完整研究与本地资源
```

只需一个主要研究入口时，不把每个子页面拆成重复卡片。卡片可带「当前方案」「IDE 效果」「研究材料」子链接；作者字段应可见且可搜索。返回分类的链接必须有实际路由行为，而不只是一个未被处理的 hash。

## 保留作者与资源来源

新增研究署名使用用户确认的信息。保留原有研究作者、原启动页来源、组件与图标来源。不要执行从他人仓库继承的身份设置脚本，或仅因模板要求就把提交作者伪装成原仓库主人；使用已配置的真实身份或连接账号，身份冲突时明确处理。

仅复制发布需要的资源。排除缓存、临时 Figma URL、开发机绝对路径、访问凭证和无关测试输出。独立文档应能说明结论、参数、证据限制及出处。

## 核对与提交

验证新增入口、子链接、返回分类、作者搜索、缩略图及研究页面。检查已有条目未被意外删除或重署名。

是否提交、推送或发布取决于当前请求；仅仅调用本技能并不授权外部变更。已获得对应授权则继续，不重复询问。优先使用现有仓库工作流和可用的 GitHub 连接；需要通过 Git API 更新时，基于当前 tree 构建增量提交，使用预期分支 SHA 防止覆盖并发修改。预期 SHA 冲突后读取新状态并协调，不强制覆盖。

文本与二进制按各自工具支持的编码上传；不要把 PNG 当 UTF-8 写入。API 返回成功后复核最终提交及变更范围。

## 发布状态与停止条件

GitHub 提交成功不意味着 Pages 可用。核对发布配置或构建状态，并请求公开地址，确认页面和关键资源已更新。HTTP 404 本身不能证明是哪一项设置出了问题。

若 Pages 未启用且用户请求发布，在可用权限内设置合适来源。静态根目录网站通常可使用 `main` / `/ (root)`；已有 Actions 或其他发布配置则沿用实际流程，不一律改成分支发布。

认证、权限或浏览器工具不可用时，完成不依赖它们的合入工作。短暂故障可有限重试；相同失败再次出现后不要无限重试、创建额外发布渠道或扩大权限。交付已完成的提交/材料链接，准确说明线上状态以及唯一必要的用户操作。
