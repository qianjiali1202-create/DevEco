# 可分享研究页面

这个 Skill 负责交付形态：让别人打开一条稳定链接就能理解材料、复现关键状态，并找到研究正文和机器可读参数。

## 页面结构

DevEco 研究页面默认放在：

```text
analysis/<slug>/
├── index.html
├── styles.css
├── app.js              # 有交互时
├── data.js             # 数据较多时
├── README.md
├── RESEARCH.md
├── VALIDATION.md
├── *-tokens.json       # 有设计参数时
└── assets/
```

只创建实际需要的文件。页面使用仓库现有组件、Token、字体和相对路径，不重复建立一套视觉系统。

## 链接与状态

- 稳定入口始终是 `analysis/<slug>/index.html`，不要因版本更新改变路径。
- 章节定位使用语义化 hash，例如 `#comparison`、`#lab`。
- 会影响别人看到哪一屏的交互状态使用语义化查询参数；非法或未知参数退回默认值，不使页面报错。
- `v` 参数只用于缓存版本，不承载业务状态。
- 已经分享过的旧路径要保留；无法保留时提供重定向或兼容入口。

## 研究交付

- 页面明确区分事实、来源、推断和设计建议。
- 关键结论在页面中可直接扫描，完整证据与边界保存在 `RESEARCH.md`。
- 有可调参数时提供 JSON Token；有交互时在 `VALIDATION.md` 记录验证范围。
- 引用外部组件或设计系统时标明来源及复用边界，不把近似实现写成官方组件。

## 合入 DevEco

1. 在 `site/catalog.js` 的合适分类登记页面，保留作者字段。
2. 在 `README.md` 增加入口或更新现有说明。
3. 必要时更新启动页资源的缓存版本参数。
4. 保留 `.nojekyll` 和已有 GitHub Pages 发布方式。
5. 用户明确要求提交或发布时，配合 `$repository-publish` 完成远端更新与线上验证。

## 验证

- 桌面和窄窗口均无整页横向溢出；宽表可以局部滚动。
- 所有章节、交互控件、下载文件和外部来源链接可访问。
- 浏览器没有 JavaScript 异常或失败资源。
- 带 hash、查询状态和缓存版本的链接能打开预期视图。
- 最终给出稳定页面链接、关键状态示例链接、研究正文与 Token 链接。
